2. Contact Form Backend

The contact form currently shows an "honest failure" state because no backend endpoint is configured. To activate form submissions, choose one of these options:

Option A: Formspree (Easiest — No Backend Required)

  1. Create an account at formspree.io
  2. Create a new form and note your Form ID (e.g., xpzgkqrb)
  3. Open js/main.js and find the initContactForm() function
  4. Replace the simulated fetch with:
const response = await fetch('https://formspree.io/f/YOUR_FORM_ID', {
  method: 'POST',
  headers: { 'Accept': 'application/json' },
  body: new FormData(form),
});

if (response.ok) {
  formBody.style.display = 'none';
  formSuccess.classList.add('show');
} else {
  throw new Error('Submission failed');
}

Option B: EmailJS (Client-Side Email Sending)

  1. Create an account at emailjs.com
  2. Set up a service, template, and get your Service ID, Template ID, and Public Key
  3. Add the EmailJS SDK in index.html before js/main.js:
<script src="https://cdn.jsdelivr.net/npm/@emailjs/browser@4/dist/email.min.js"></script>

Then in the form handler:

emailjs.init('YOUR_PUBLIC_KEY');
await emailjs.send('SERVICE_ID', 'TEMPLATE_ID', {
  from_name: data.name,
  from_email: data.email,
  message: data.description,
  service: data.service,
});

Option C: Custom API Endpoint

If you have a backend server (Express, Next.js API route, etc.):

const response = await fetch('/api/contact', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(data),
});

⚠️ Security: Never expose API keys in client-side JavaScript. Use server-side environment variables and proxy API calls through your backend.

3. Domain Configuration

Before going live, update the following in index.html:

<!-- Update canonical URL -->
<link rel="canonical" href="https://YOUR-DOMAIN.com/">

<!-- Update OG URL -->
<meta property="og:url" content="https://YOUR-DOMAIN.com/">

<!-- Update structured data URL -->
"url": "https://YOUR-DOMAIN.com"

4. Analytics (Optional)

For privacy-respecting analytics, we recommend Plausible or Umami. Add the snippet in index.html before </head>:

<!-- Plausible Analytics -->
<script defer data-domain="yourdomain.com"
  src="https://plausible.io/js/script.js"></script>

5. Hosting Options

This is a static website — no build step required. You can host it on:

  • Netlify: Drag and drop the folder, or connect via Git. Free tier available.
  • Vercel: Deploy via CLI or Git integration.
  • GitHub Pages: Push to a repository and enable Pages.
  • Cloudflare Pages: Fast global CDN with free tier.
  • Any standard web hosting with FTP upload.

6. SEO Checklist

  • ☐ Update <link rel="canonical"> with your real domain
  • ☐ Update Open Graph og:image with a real 1200×630 image
  • ☐ Update the Organisation structured data with real contact details
  • ☐ Add real social media profile URLs to the sameAs array in structured data
  • ☐ Configure Google Search Console after deployment
  • ☐ Submit sitemap (create manually or via a tool)

7. Sitemap

Create a sitemap.xml in the root directory:

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://yourdomain.com/</loc>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://yourdomain.com/pages/privacy.html</loc>
    <priority>0.3</priority>
  </url>
  <url>
    <loc>https://yourdomain.com/pages/terms.html</loc>
    <priority>0.3</priority>
  </url>
</urlset>

8. robots.txt

Create a robots.txt in the root directory:

User-agent: *
Allow: /
Disallow: /pages/setup.html

Sitemap: https://yourdomain.com/sitemap.xml

9. Performance Tips

  • Host fonts locally using @font-face for faster load times
  • Convert images to WebP format if you add any
  • Enable GZIP/Brotli compression on your host
  • Add <link rel="preload"> for the CSS file
  • Use a CDN for static assets
